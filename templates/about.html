Technical Specification & Architecture

CryptoVault System Architecture

A disciplined, 5-layer server-rendered cryptocurrency platform designed and developed by Adabala Pushkaran (24EG105R65).

1. Five-Layer Separation of Concerns

CryptoVault strictly isolates concerns so each layer only communicates with its immediate neighbour. This maintains unambiguous security boundaries and clean testability.

Layer 1: Presentation (Thymeleaf & Minimal React/Vanilla Islands)
Full server-side rendering for instant First Contentful Paint, SEO crawlability, and small JS payload for live ticker and interactive charts.
Layer 2: Security & Routing (Spring Security 6)
Intercepts requests, enforces authentication, verifies CSRF tokens on all POST requests, and restricts admin routes via ROLE_ADMIN.
Layer 3: Controller Layer (Spring MVC & REST)
Handles HTTP request parameters, DTO validation, model binding, and delegates business workflows to the service layer.
Layer 4: Business & Service Layer (@Transactional)
Contains business rules: address generation, atomic debit-credit balance updates, fee calculations, and notification triggers.
Layer 5: Data Access & Relational Persistence (Spring Data JPA + MySQL)
Normalized schema mapping 6 entities (User, Wallet, Currency, Transaction, AuthSession, Notification) with ACID consistency.
